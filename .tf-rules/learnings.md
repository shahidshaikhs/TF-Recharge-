## Recent
[chat] Custom-element section JS that uses ES `import` (e.g. `import { Component } from '@theme/component'`) MUST be loaded via `<script src="{{ 'file.js' | asset_url }}" type="module" fetchpriority="low"></script>` in the section. Do NOT use a `{% javascript %}` block — Shopify bundles that into the non-module `scripts.js`, causing "Cannot use import statement outside a module" and the custom element never registers. The `@theme/*` importmap aliases are defined in `snippets/scripts.liquid` and only resolve inside `type="module"` scripts.
[chat] Recharge storefront SDK (`window.recharge`) does NOT reliably initialize inside the theme editor preview iframe — test bundle/subscription features on the real storefront preview URL (`/pages/<handle>?preview_theme_id=<id>`), not the customizer.
[chat] This theme currently has NO color schemes defined (config/settings_data.json has no `color_schemes`, settings_schema.json has no color-scheme group) — the theme editor shows a "color schemes must be defined" warning theme-wide and `color-{{ section.settings.color_scheme }}` classes resolve to blank.
[chat] In this theme's `Component` framework (assets/component.js), `on:click`/`on:change`/etc. handlers are delegated from a single listener on `document` with `{capture:true}`. Inside a handler, `event.currentTarget` is `document` (throws "Cannot read properties of undefined" on `.dataset`). The framework proxies `event.target` to return the element carrying the `on:...` attribute — ALWAYS read the clicked element's dataset via `event.target`, never `event.currentTarget`.
